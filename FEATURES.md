# Features

What the site does, where each feature starts, where it lives, and how to check it. Keep this current as features land; the agent or contributor changing a feature updates its row in the same change.

| Feature | Where it starts | Where it lives | How to check it |
| --- | --- | --- | --- |
| Landing page | Visitor opens `/` | `src/pages/index.astro` | `npm run build`, then read `dist/index.html`; story sections, invoice panel, pricing |
| Founder story page | Visitor opens `/about` | `src/pages/about.astro` | Build and read `dist/about/index.html`; what Will listens for, the partnership section with the cofounder portrait plate. It tells no beat the landing page already tells — the origin and the pitch live on `/` |
| Journeyman product page | Visitor opens `/journeyman` | `src/pages/journeyman.astro` | Build and read `dist/journeyman/index.html`; Rust & Iron theme via `<body data-theme="journeyman">`. Sections: what the product is, the askable library (the flagship surface, shown as the working demo, skinned per customer and isolated per plant), how an engagement runs, the recording and consent commitments (`#trust`, binding language from the Knowledge Capture Agreement Sections 4.3–4.5 and Attachment B — pause and deletion rights, no biometrics, no performance evaluation, non-consenting people excluded, encryption and access logging, retention), who it fits, and the two fee halves (capture quoted per project, library monthly from delivery) |
| Askable-library demo | Visitor reaches `#library` on `/journeyman` | `src/components/AskLibraryDemo.astro` (markup + client script), `src/lib/library-demo.ts` (the four-job sample corpus), `src/lib/retrieval.ts` (the matching), demo styles in `src/styles/global.css` | `npm run build && npm run check:demo`. In the browser: clicking a question retrieves its slip, typing a paraphrase retrieves the same one (`why does the slide keep starving for oil` -> SEG 09; `door sensor says open` -> SEG 02), and a question the sample can't answer gets the miss state rather than a guess (`how much coolant should the sump hold`). With JavaScript off, the first question, its answer, and its source segment still render. Nothing is fetched: the answers, keywords, and source stamps are all in the markup |
| Shared shell (header, footer, fonts, meta) | Every page render | `src/layouts/BaseLayout.astro`, `src/components/` | Change a nav label in `SiteHeader.astro`, rebuild, see it on all three pages |
| Design system and Journeyman theme variant | Any visual change | `src/styles/global.css` (tokens mirror `DESIGN.md`, the normative spec); theme override on `body[data-theme="journeyman"]` | Compare `/` and `/journeyman` palettes; reduced-motion block near the Responsive section |
| Drop-in portraits (founder and cofounder) | Copy a PNG into `public/` | `src/lib/schema.ts` detects `public/will-wollack.png` and `public/ethan-davidson.png` at build time via `existsSync` and exports root-relative and absolute URLs; `about.astro` renders plates with a typographic placeholder when absent | Delete a PNG, rebuild: placeholder renders and JSON-LD drops the image; restore it and rebuild to reverse. Absolute URLs feed Person JSON-LD |
| Brand mark (logo, favicon, app icon) | Header lockup, browser chrome, social card, JSON-LD | `public/logo.png` (canonical raster), `src/lib/brand.ts` (`MARK_PATH`, the derived small-size silhouette), `src/components/BrandMark.astro` (lockup), `src/pages/favicon.svg.ts` (adaptive favicon), `public/favicon-32.png` and `public/apple-touch-icon.png` (tile variant), `src/lib/schema.ts` (`Organization.logo`/`image`) | `npm run build`, read `dist/favicon.svg` and the header markup: all three render the one path in `brand.ts`. Delete a tile PNG, rebuild, confirm the fallback `<link>` breaks. View the built site's tab at 16px and 32px in light and dark chrome |
| SEO metadata and social cards | Every page's `<head>` | `BaseLayout.astro` (canonical, Open Graph, Twitter), per-page title/description props | View source on a built page; canonical must end in `/` and match the served URL |
| Structured data (JSON-LD) | Every page's `<head>` | `src/lib/schema.ts` builds entities, `src/components/JsonLd.astro` emits them | Paste a built page's JSON-LD into validator.schema.org |
| Sitemap and robots.txt | Crawlers | `astro.config.mjs` (`site` is the single source of truth) + `@astrojs/sitemap` emit `sitemap-index.xml`; `src/pages/robots.txt.ts` points at it | `npm run build`, then check `dist/sitemap-index.xml` and `dist/robots.txt` |
| CI checks | Pull requests, and every push to `main` | `.github/workflows/ci.yml` builds, then runs `npm run check:all` — the `astro check` type-check plus the four guards (`check:copy`, `check:demo`, `check:contrast`, `check:language`). `.github/workflows/deploy.yml` runs the same gate against the `dist/` it publishes, so the deploy job waits on it | Open or update a PR, or push to `main` and watch the `deploy` run. A welded word (a missing space where a text node meets an inline element, caused by Astro's line-break whitespace rules), a question chip that no longer reaches its answer, a token pair below WCAG AA, or a gendered pronoun in the copy fails the matching guard, which prints the block or sentence it found. On a push to `main` that failure stops the publish: the `build` job fails, `deploy` is skipped, and production still serves the previous commit |
| Pages deploy | Push to `main` | `.github/workflows/deploy.yml` builds, runs `npm run check:all` (type-check + guards), then publishes via the GitHub Actions Pages source | `gh run list` on the repo; verify production after each deploy. Either a guard failure in the `build` job or a red `deploy` job means the push is not live |

## Limitations

- Exactly one script ships: the askable-library demo on `/journeyman` (`AskLibraryDemo.astro`), inlined into that one page and offline by contract — no fetch, socket, or import, which `check:demo` enforces. Everything the demo says is rendered markup, so it degrades to a readable question, answer, and source without JavaScript. Any further interactivity is still out of scope for this stack; the rest of the site is CSS only (hover reveals, sticky header, smooth anchors).
- The demo's corpus is four canned jobs with canned keyword indexes, so free-text questions outside those four get the miss state rather than an answer. Recall depends on the keywords listed in `data-ask-match`; a new job needs its own chip, answer slip with a source stamp, and index — and, if its question is one the battery should cover, an entry in `scripts/check-demo.mjs`.
- The demo's retrieval is keyword overlap, not meaning: it needs two matching keywords, or one when the question is a bare lookup, so a heavily reworded paraphrase can miss a job the record does cover. That trade is deliberate — an honest miss beats a confident wrong answer — and the battery pins both halves of it.
- The deploy gate runs the type-check after the build, not before it: `withastro/action` builds first and `npm run check:all` then runs `astro check` and the guards in one script. A type error still stops the publish — only the ordering is decided by the guards needing `dist/`.
- The preview webview in the Freebuff desktop app cannot resize below 613px and may not composite frames for screenshots; verify phone-width behavior with a real browser, devtools device mode, or a same-origin iframe probe.
- Portrait URLs are resolved at build time, so adding or removing a PNG requires a rebuild to take effect.
- Contact CTAs are plain `mailto:` links; there is no form or backend by design.
- The brand mark's small-size silhouette is derived from `public/logo.png` by hand (recipe in `DESIGN.md`), not at build time: replacing the raster means re-deriving `MARK_PATH` and re-rendering the two tile PNGs in the same change.
- `about.astro`'s photo-placeholder motif still uses a Unicode gear. It only renders when `public/will-wollack.png` is absent, and it is part of the portrait treatment, so it was left alone; if the portrait is ever removed, switch that motif to the brand mark.
